# HW-101: The memory corrected errors

The memory controller counted errors in the memory that it corrected, since the machine started (`ce_count` in `/kernel/devices/system/edac/mc/mc0`). The memory has error correction, which made each error right before any program saw it, so nothing was lost. A single corrected error is not a fault. A count that rises from day to day is, since memory that needs correcting is often starting to fail.

## What to do

1. Run `elevate hardware check memory` to see the count, and `elevate dmesg | grep "Machine check"` to see which memory the errors came from: the lines name the CPU, the bank and the channel.
2. Restart the machine and choose *Test the memory* in the start menu. It tests all of the memory, which `hardware check` cannot do while the system runs.
3. Check again a day later. If the count started again from 0 at the restart and is rising again, replace the memory module the errors name.
4. To check that it worked, run `elevate hardware check memory` after the restart with the new module, and see `none counted since the start`.
