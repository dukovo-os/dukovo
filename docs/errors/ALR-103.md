# ALR-103: A webhook's server refused the message

alertd posted the message to the address of a `[[webhook]]` in `alerts.toml`, and the service answered with a status that is not a success, which `alerts test` shows in the service's own words: `ntfy answered 403 Forbidden: forbidden`. Nothing was delivered. A refused message stays in the outbox, tried again after 1, 5, 15 and 30 minutes and then every hour, and is dropped when it is 24 hours old. alertd never prints a webhook's address or token, so the line names the kind and the host alone.

## What to do

1. Read the status and the service's words after it. 401 and 403 mean that the service did not accept the token, or that the topic needs one. 404 means that the address names nothing, as a Slack or Discord webhook that was deleted does. 5xx is the service being down, and alertd tries again by itself.
2. Make the address or the token right on the Alerts page: remove the webhook and add it again, or edit the `[[webhook]]` in `/system/settings/alerts.toml` and run `elevate service alertd reload`.
3. To check that it worked, choose **Send a test alert**, or run `elevate alerts test`: the line for the webhook says that it was sent.
