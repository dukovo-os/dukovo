# SEC-130: An update is waiting

The last time Dukovo looked at the update server, it found a newer release of the system that this computer takes now, and the release is not installed. The line names it and says when it was found. Updates carry security fixes, and a computer that waits runs with the faults the new release mends. By default Dukovo tells whoever signs in, and changes nothing by itself.

## What to do

1. Run `update` to see what waits: the system, the firmware and the apps.
2. Run `elevate update apply`. It stages the system update in the spare slot, to start at the next restart, which you choose.
3. Restart when it suits you. The new release proves itself as it starts, and the computer goes back to the one before if it does not.
4. A release you hold back on purpose is not warned about. The hold is for a while, not for good, and `elevate update unhold system` lifts it. Nor is one you put off with `elevate update later system --for 7d`, until the week is over; `elevate update later system --off` brings it back, and so does an advisory that the release fixes.
5. To check that it worked, run `elevate dukovo-check` after the restart and an update check: the line for `waiting` passes.
