# APP-102: The catalog's file is not the one whose sheet you read

`bundle sheet ID` shows the sheet of the file the catalog offers, and its JSON gives that file's SHA-256 as `sha256`. `bundle install ID --sha256 HEX` installs only a file that has that SHA-256, so that what is installed is what the person agreed to when they read the sheet. The catalog lists another file for the app now, most often a newer version published since the sheet was read, so bundled refused before it fetched or unpacked anything. Nothing was installed.

The web console says it as "The catalog has a newer version than the sheet you read", and offers to read the sheet again.

## What to do

1. Read the sheet again: `bundle sheet ID`, or **Read it again** in the console. It shows the file the catalog offers now, with the permissions, services and data it asks for, which can differ from what the first sheet said.
2. If it is what you want, install it: `elevate bundle install ID --for-everyone`, which shows the sheet and asks, or the same with `--sha256` and the new `sha256`, which installs only that file.
3. If the app is not wanted any more, do nothing: nothing was changed.
4. To check that it worked, run `bundle list`: the app is listed with the version the new sheet showed.
