# NET-174: The update server's certificate is not valid by this clock

With `--internet`, the update server answered, but its certificate is not valid now by this machine's clock: the clock is before the certificate's start or after its end. A certificate is valid only between two dates, so a clock that is years wrong, as one with a flat battery is, fails every TLS connection. The message shows what the clock says.

## What to do

1. Run `timedatectl` to see the time the machine has: if it is wrong, that is the cause.
2. Check whether timed sets it: `timedatectl timesync-status` says which server it asked. A network that blocks time servers leaves the clock as it was, which is NET-141.
3. Set the clock by hand: `service timed stop`, then `timedatectl set-time` with the time, as `2026-11-13 09:30:00`, and `service timed start` to have timed keep it right.
4. If the clock is right, the server's certificate is out of date: tell whoever runs the server.
5. Run `netcheck --internet` again.

netcheck(8), timed(8), timedatectl(1), the handbook's chapters "Networking" and "Checking the network".
