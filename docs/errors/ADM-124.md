# ADM-124: The API token may not do this

The request came with an API token whose scopes do not cover what it asked for. A scope names an area of the console, such as `services`, and lets the token read and change it; `services:read` lets it only read; `*` lets it do anything its owner may. The detail names the scope the action needs. Nothing was run.

A token reads the tasks of the actions whose area its scopes let it read, and stops one only when its scopes let it change that area and its owner is the task's person or an administrator; a task whose action the console no longer has has no area to check, so no token may stop it. A token does not read the journal, "What changed", which names people and files: it, Keep it and Put back take a signed-in session.

The same ID answers a token sent to a part of the console that is not for tokens, such as the account and sign-in routes: a token is for the actions, their list (`GET /api/1/actions`), showing one (`POST /api/1/show`) and the tasks, only.

## What to do

1. Make a token whose scopes name the area, and use it for this script. Give each token the fewest scopes its script needs.
2. If the request was for an account or sign-in route, or for the journal, use the console's page instead: those take a signed-in session, never a token.
