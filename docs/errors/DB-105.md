# DB-105: There is no certificate of that name

Other machines connect to PostgreSQL over TLS only, with a certificate that certd keeps. `database allow` uses the certificate it is given with `--certificate`, or `this-machine`, the machine's own, when it is given none. certd has no certificate of that name, so PostgreSQL could not be set up to present it. Nothing was changed.

## What to do

1. Run `cert list`: it lists the certificates certd has, by name.
2. Use one of them: `elevate database allow NAME --from NETWORK --certificate CERTIFICATE`. A certificate that covers the name the other machines use to reach this one avoids their warnings: `cert show CERTIFICATE` lists the names it covers.
3. Or get one that is not there yet: `elevate cert get NAME` orders one from Let's Encrypt, or `elevate cert add` takes one you have.
4. To check that it worked, run `database allow` again: it restarts PostgreSQL, and the `ssl` of `elevate database list --json` is on.

## See also

database(8), cert(8), the handbook's chapter on certificates and its chapter on PostgreSQL.
