# ALR-106: A channel's about names no kind of alert

A channel in `/system/settings/alerts.toml` can be told of only some kinds of alert, with `about`, a list of the words `data`, `stopped` and `hardware`. alertd read the list and found a word that is no kind, or a list that is empty or is not a list of words. The log says which channel and which word, as `alerts.toml: webhook 2: about names colour, which is no kind of alert (ALR-106)`. This is the one setting for which a mistake does not leave the channel out: a list can only narrow what a channel is told, so alertd reads a mistake as no narrowing. It leaves out a word it does not know and goes on with the others; with no word it knows, or with a list that is empty or is not a list, the channel is told of every kind. No alert is lost to a mistake in `about`.

## What to do

1. Read the line in `log alertd`. It names the channel (`[email]`, or `webhook` and its number in the file) and the word.
2. Set the kinds with `elevate alerts channel email --about data,stopped`, or `elevate alerts channel webhook:2 --about hardware`, which write the list as alertd reads it. `--about all` removes it. Or edit `about` in the file by hand: it takes `"data"` (a disk failing, a filesystem nearly full, a backup failed or late), `"stopped"` (a service, an update or a start that failed, a certificate running out, memory low) and `"hardware"` (a sensor or a disk running hot).
3. Run `elevate service alertd reload`, which reads the file again.
4. To check that it worked, `elevate alerts status` names what each narrowed channel is told of ("told of: data at risk, hardware"), and `log alertd` has no line with this ID.
