# CRT-103: The firewall closes port 80, which the authority must reach

An authority that proves a name by HTTP connects to port 80 of the name's address. The firewall's rules in `/system/settings/firewall` do not let it in. `cert get` answers the authority as a command of an administrator, which takes connections only when a rule allows them, so a firewall with no rule for port 80 fails the check; certd, which renews a certificate by the same means, is a service that names port 80 and needs no rule, but a rule that denies the port closes it for both. A router or a provider's firewall in front of this machine is not seen by the check: only asking the authority shows it.

## What to do

1. Run `firewall list`, which numbers the rules, and see whether a `deny` rule covers port 80. The first rule that matches decides, so a rule that denies it before the one that allows it wins. Take such a rule away with `elevate firewall remove NUMBER`.
2. Open the port: `elevate firewall allow tcp 80`, or **Open port 80** on the Certificates page, which opens it as a trial that you keep once the certificate has come.
3. Keep the rule. certd renews the certificate by the same way, and the authority must reach port 80 each time. A certificate proved by DNS needs no rule.
4. If the machine sits behind a router, forward port 80 to it there.
5. To check that it worked, run `elevate cert get NAME --check`: the line for the firewall says that port 80 is open and which rule does it.
