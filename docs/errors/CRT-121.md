# CRT-121: A certificate's renewal keeps failing

certd renews a certificate that `cert get` got by HTTP at the day it chose, and tries again at each look, about every 12 hours, when a renewal fails. From 14 days before the certificate runs out it raises an alert, `certificate:NAME`, with the words of its sign-in notice: "The certificate NAME could not be renewed: WHY. It runs out on DATE." The alert is a warning, and critical from 7 days left; once the certificate has run out, it is CRT-122. It clears by itself when the certificate is renewed, replaced or removed. The reason is the authority's or this machine's, in words, and the certificate that is in use keeps serving until it runs out.

## What to do

1. Read the reason in the alert, on the Certificates page under Renewals, or with `cert history NAME`, and `log certd`. The usual ones have a page: the name no longer leads to this machine (CRT-101, CRT-102), port 80 is closed or held (CRT-103, CRT-106), the clock is wrong (CRT-105). An authority that refuses for its limits says so: wait for the time it names.
2. Mend the cause, then renew now: **Renew now** on the Certificates page, or `elevate cert renew NAME`. A certificate that was proved by DNS is not renewed by certd; get it again with `elevate cert get NAME --dns`.
3. If the name is not used any longer, take the certificate away with `elevate cert remove NAME`, which is refused while a service's file names it.
4. To check that it worked, run `cert list`: the certificate shows a new end day, and the alert is gone from `alerts list`.
