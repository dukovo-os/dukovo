# CRT-113: The certificate is not valid now, names nothing, or is an authority's

`cert add` checks the first certificate of the chain, the server's, before it trusts anything of it. The line says which check failed:

- The certificate ran out, or starts on a day that is not yet: its dates do not hold now. Check the clock first (CRT-105): a wrong clock makes a good certificate look not yet valid.
- It names no host: its subject alternative names have no DNS or IP name, which is where clients look. A certificate that only has a common name is not taken.
- It is a certificate authority's, not a server's: the chain was put in the wrong order, with an intermediate or a root first.

Nothing was added.

## What to do

1. For dates, get a new certificate from the authority that made it. A certificate that has run out cannot be added. If it starts later, add it then.
2. For a certificate that names nothing, have the authority make one that lists the host's name or address as a subject alternative name.
3. For the wrong order, put the server's certificate first in the file and the intermediate certificates after it.
4. Add it again: `elevate cert add NAME --chain FILE --key FILE`, with `--replace` for a name that was added by hand.
5. To check that it worked, run `cert list`: the certificate is there with its days left.

cert(8), CRT-105, CRT-111, CRT-112, the handbook's chapter on certificates.
