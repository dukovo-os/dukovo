# ADM-105: Too many tries: wait a moment

The console has had as many sign-in requests as it takes from this address in a minute: ten, counting each password, code and passkey request. It answers without asking authd, and the answer says in `Retry-After` how many seconds to wait. The detail is "too many sign-in requests from this address". The same ID also appears for a session's worker that has as many calls waiting as it takes, 16 (it runs 8 of them at once, and the rest wait their turn), for an address that has given 10 wrong API tokens in a minute, which is stopped until the minute is over, even with a right token, for an action that runs as an administrator when 32 elevated commands run already (the commands of tasks count too), and for a long action asked for when 64 tasks already wait for a place; the detail says which.

This is a limit of its own, apart from the wait that authd puts on a wrong password or code, which makes the page slow to answer with ADM-101 or ADM-102. People who share one address, as they do behind one router, share the count.

## What to do

1. Wait for the number of seconds the page gives, then try once.
2. A script that signs in over and over has to slow down.
3. For a worker with too many calls, or too many elevated commands, wait a few seconds and try again. A long action that is asked for while 32 tasks run is not refused until 64 more wait: it waits, as `waiting`, and runs when a place is free.
4. A script whose token is not accepted (ADM-115) has to be given a right one, not to try again.
