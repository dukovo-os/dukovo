# HW-105: The next start is taken already

The start menu takes one start for something other than the usual one: an update waiting to be tried, or a try of `changes bisect`. A memory test at the next start is such a start too, and the menu has only one of them at a time. The message says which one is waiting. Nothing was asked, and what was waiting is as it was.

`changes bisect` gives the same answer the other way round, while a memory test is asked for the next start. The menu also does not start the slot that runs now for a test when that slot is not the one it starts by default; the message says so.

## What to do

1. Read the message: it says what holds the next start.
2. If an update waits to be tried, restart the machine to try it, and ask for the memory test after the start that tries it; or run `elevate sysupdate unstage` to put the update away.
3. If a search of `changes bisect` waits on a try, restart to take the try, or end the search with `elevate changes bisect --stop`.
4. If a memory test is asked and a search is wanted first, run `elevate hardware memtest --cancel`.
5. To check that it worked, ask again: `elevate hardware memtest --next-start` must say that the next start tests the memory.
