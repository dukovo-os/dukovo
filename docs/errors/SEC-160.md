# SEC-160: No snapshot is made of the people's files

Dukovo keeps a read-only snapshot of `/users` and `/shared` each day, so that a file that was deleted, overwritten or encrypted by mistake comes back from a day before. The line says that the `snap` service is off, or that `/system/settings/snap.toml` lists places that leave out `/users` or `/shared`, so that no snapshot is made of what it names. A snapshot shares the disk with what it was made of, so it is no copy of the disk and no protection from its failure: keep a backup too.

## What to do

1. Run `service snap explain` to see whether the service runs and why not.
2. If it is off, run `elevate service snap enable`, which also starts it.
3. If `snap.toml` has a `places` line, make it hold `"/users"` and `"/shared"` as well as what else you snapshot, or take the line out for the default places: `/users`, `/shared` and `/system/settings`. The service reads the file at each round, every hour, so it needs no restart.
4. Run `snap list` to see the snapshots that exist. The first one of a day comes in the hour after the service starts. `elevate snap create /users` makes one at once.
5. To check that it worked, run `elevate dukovo-check`: the line for `snapshots` passes.
