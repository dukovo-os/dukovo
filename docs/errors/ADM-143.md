# ADM-143: That AI client was not let in

A program called the console's MCP server, at `/mcp` or through `admin mcp`, and what it showed is not the token or the pass of an AI client that may connect. The detail says which of these it is:

- The token or the pass is not one of this machine's. A token is shown once, when its client is added, and starts with `dkc_`. A token is wrong if it was copied in part, or if its client was removed and added again, which makes a new one.
- The client has ended. Every client ends on the date chosen when it was added, a year later at most.
- The client was removed, or its owner's account was removed, renamed, disabled, or is no longer an administrator's or may no longer use the console.
- It is an API token, which starts with `dkv_`. An API token works at `/api/1` and not at `/mcp`, and an AI client's token works at `/mcp` and nowhere else.

A wrong token counts as a wrong password does: the next try waits longer each time, and an address that keeps trying is blocked for a while (blocking.toml(5)).

## What to do

1. On the AI clients page, or with `admin mcp list`, look at the client: whether it is there, and when it ends.
2. If it has ended or its token is lost, remove it and add it again, then give the AI client its new settings. The page shows them once the client is added.
3. For a client that connects over SSH, run `ssh NAME@HOST admin mcp CLIENT --check`: it says what the client may reach, or why it is not let in.
4. `elevate log --service authd --grep "AI client"` shows each refusal with its reason.
