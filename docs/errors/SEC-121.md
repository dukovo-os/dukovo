# SEC-121: No account is an administrator

No account of a person that is not disabled is in the group `admins`. Nobody can run a command as root with `elevate`, so nothing can be repaired, updated or set up from a sign-in, and Rescue, which asks for one of the computer's administrators before it repairs anything, asks for nobody on a computer that has none. This happens when the last administrator was disabled or made an ordinary account after the question that warns of it was answered yes.

## What to do

1. Have root's shell without signing in. At the boot menu, edit the entry's kernel command line (in GRUB, select the entry and press `e`) and add `console-sign-in=off`, as the handbook's chapter on users says under "Root's shell without signing in". Whoever can do this can run anything as root already, so it gives no one more. A server is reached through its console, its serial port or its cloud provider's console.
2. In that shell, run `user list` and pick the account that should administer this computer, then `user set --admin NAME`. If the account is disabled, `user enable NAME` first. If it has no password you know, the startup-trouble entry of the boot menu resets one.
3. Restart the computer without the added flag.
4. To check that it worked, sign in as that person and run `elevate dukovo-check`: the line for `administrators` passes and names them.
