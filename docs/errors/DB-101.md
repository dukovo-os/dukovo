# DB-101: PostgreSQL is not installed, not running, or does not let root in

`database` signs in to PostgreSQL over the socket of its service, `/system/live/services/postgres/.s.PGSQL.5432`, as the role `postgres`. It needs no password: the first line of the server's `pg_hba.conf`, `local all postgres peer map=administrators`, has `pg_ident.conf` map the account root, which is who `elevate` runs a command as, to `postgres`. The line names which of three things stopped it. PostgreSQL is not installed for everyone. Its service is off, or not ready yet: the first start makes the cluster, which takes a while. Or the server asked for a password, which means that the first line of its `pg_hba.conf` was changed. Nothing was changed.

## What to do

1. If it is not installed, install it: the Add an app page of the web console, or `elevate bundle install org.postgresql.postgresql --for-everyone`.
2. If it is off, run `elevate service postgresql enable`, which starts it. `service postgresql explain` says in a sentence why a service is not running, and `service postgresql status -n 0` shows its state.
3. If it did not let root in, open `elevate nano /shared/services/org.postgresql.postgresql/postgres/data/pg_hba.conf` and put the first line back as the bundle's own `pg_hba.conf` has it, then run `elevate service postgresql reload`.
4. To check that it worked, run `elevate database list`: it lists the server and its databases.
