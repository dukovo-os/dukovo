# WEB-101: A website already answers to that name

`website add` refuses a name that nginx already serves. A site is a file in `/system/settings/websites`, and a name is taken when a file there or a `server_name` in nginx's own `nginx.conf` holds it. The line names the file. Nothing was changed: no folder was made, and no setting was written.

## What to do

1. Read the line: it names the file that holds the name, and the name.
2. If the file is another site that `website` added, run `website list` to see it. To give the name to the new site, remove the old one with `elevate website remove NAME`, which keeps its folder unless you add `--files`. To change the old site, `elevate website https NAME --certificate CERTIFICATE` gives it HTTPS, and its file in `/system/settings/websites` is yours to edit.
3. If the file is `nginx.conf`, a server of your own answers to the name. Take the name out of its `server_name`, or give the new site another name.
4. To check that it worked, run `elevate website add NAME --owner ACCOUNT --dry-run --json`: no check of the plan fails.

website(8), nginx's section of the handbook's chapter on running services, WEB-102.
