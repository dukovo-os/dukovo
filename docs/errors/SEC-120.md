# SEC-120: A person's account has no password

An account of a person, one that is not a service's and not disabled, has an empty password. Anyone at the keyboard, or at the serial port, can sign in as that person by typing nothing at the password prompt, and if the account is an administrator's, can run anything as root. SSH refuses an empty password, so the risk is to whoever can reach a sign-in on this computer itself. The line names the accounts.

## What to do

1. If the account is used, have its person sign in and run `passwd`, which asks for the new password twice. That also keeps the person's keyring, which a password set by an administrator would empty if it was not open.
2. If the person cannot be there, an administrator sets it with `elevate passwd NAME`. Dukovo warns of a short password, and the person should change it at their next sign-in.
3. If nobody uses the account, disable it with `elevate user disable NAME`. A disabled account is no risk, and is not warned about; `elevate user remove NAME` takes it away.
4. To check that it worked, run `elevate dukovo-check`: the line for `empty passwords` passes.
