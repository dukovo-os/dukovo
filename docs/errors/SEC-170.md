# SEC-170: No alert has reached anyone for a day

`dukovo-check` asked alertd about its channels. At least one is set, an email account, a webhook or a browser, and none of them took a message in the last 24 hours, while each failed in that time: its last failure is within 24 hours and later than its last success, or it has never had one. So an alert that is raised now, a disk that fails or a backup that did not run, is told on this machine's screens and at the next sign-in, and to nobody else. A machine with no channel is not told of this: that is how every machine starts, and the Overview says that no alert leaves it.

## What to do

1. Run `elevate alerts status`. It names each channel, its last success, and its last failure with the words of the server that refused, and the error ID when alertd knows the kind: ALR-101 to ALR-105.
2. Follow the page of the ID: a password the mail server refuses, a server with no TLS, a webhook that is refused, a browser that ended its subscription or a push service that refuses.
3. Run `elevate alerts test`, or **Send a test alert** on the Alerts page. Each channel says how it went.
4. To check that it worked, run `elevate dukovo-check`: the line for `reach` passes.
