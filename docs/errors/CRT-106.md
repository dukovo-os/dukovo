# CRT-106: Another program holds port 80

To prove a name by HTTP, `cert get` answers the authority on port 80. It does so itself when the port is free, and through nginx when nginx holds the port, writing the answers to the folder nginx serves them from. The line says that a program other than nginx and certd holds the port, and names it, so there is nowhere to put the answer where the authority will look. Nothing was ordered.

## What to do

1. The line names the program. `ss -tl` shows that port 80 is listening, and `service list` the services that run, among them the one that holds it.
2. If it is a service you can stop for the few minutes the check takes, stop it with `elevate service NAME stop`, get the certificate, and start it again.
3. If it must go on, prove the name by DNS instead, which never has the authority connect to this machine: `elevate cert get NAME --dns`.
4. To check that it worked, run `elevate cert get NAME --check`: the line for port 80 passes.
