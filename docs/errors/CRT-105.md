# CRT-105: The clock is wrong

The clock reads a date before the system was made: a machine whose battery is flat starts with 1970 on its clock until `timed` sets it from the network. A certificate is valid between two dates, so with that clock the authority's certificate would look as if it came from the future, and one made now would be dated 1970. `cert get`, certd and the checks before an order refuse to go on, and the line says the date the clock shows. certd makes and judges nothing then, and looks again each minute until the clock is right. Nothing was ordered.

## What to do

1. Run `timedatectl timesync-status`. It says which time servers `timed` tried and what each answered.
2. If no server answers, the network is the cause: run `netcheck`, which finds the layer where it stops working. A firewall in front of this machine must let UDP port 123 and TCP port 4460 out. SEC-140 has the rest.
3. When the date is right, try again.
4. To check that it worked, run `elevate cert get NAME --check`: the clock line passes.
