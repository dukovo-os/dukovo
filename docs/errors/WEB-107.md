# WEB-107: The site's file was changed by hand

`website` writes a site's file from the facts it is given, and a file that differs from what it would write, or whose first line is not its own, is yours: a change made there is kept and served, and the web console shows the site as changed by hand. `website https` would have to write the file again to add the HTTPS server, which would undo what you wrote, so it refused. Nothing was changed.

## What to do

1. Add the HTTPS server to the site's file yourself. website(8) shows the server block it writes for HTTPS. Edit the file with `elevate nano /system/settings/websites/NAME.conf`, with the certificate's `fullchain.pem` and `key.pem` under `/system/live/certificates/nginx/CERTIFICATE/`.
2. Or let `website` write the file: put the site's file back as it was, which Put back under What changed on the Overview page of the web console does, or take out your changes, then run `elevate website https NAME --certificate CERTIFICATE`.
3. After an edit of your own, run `elevate website check`: nginx's check passes. Then `elevate service nginx reload` makes nginx read it.
4. To check that it worked, run `website list`: the site says it has HTTPS.

website(8), cert(8), the handbook's chapter on running services, WEB-103.
