# ADM-110: That was refused

authd refused what the console asked of it, for a reason that has no ID of its own. The detail holds authd's own words, which say what happened and what to do. Some it gives:

- "64 web console sessions are signed in already". The console holds as many sessions as it may; the same cause as ADM-120.
- "begin adding the app again: it was not begun here, or was begun more than 10 minutes ago". Add the app again from its first step.
- "the sign-in rules ask NAME for a second step: add another before removing the app". The rules in admin.toml need one, so add another before removing this.
- "NAME has a token named TOKEN: remove it, or choose another name", or "NAME has 32 tokens: remove one first".
- "recovery codes come with a second step: add an app or a passkey first".
- "give your password, or unlock the console first". A change to a second step asks for the password, or an unlocked console.
- "NAME is not an administrator, and makes no changes". Only administrators unlock and run commands as an administrator.
- "authd cannot write ...". The disk is full or read-only, so authd could not keep a change.

## What to do

1. Do what the detail says.
2. If it names a file authd cannot write, check the disk with `df` and the log of authd: `elevate log -s authd`.
3. `elevate log --audit` has authd's lines about each sign-in, unlock and change of a second step, with how each was proved.
