# UPD-104: A wanted check failed after an update

health.toml can name checks of your own, each a command that must exit with 0. A required one that fails sends the machine back to the version before the update (BOOT-103). A wanted one, which is what a check is unless it says `required = true`, does not: the update stays, and the failure is only logged. When the update was a try, sysupdate also tells alertd, which raises a warning that names the update and the check, "After the update to VERSION, the wanted check NAME failed", with the check's own reason and this ID. A start that is not a try only logs it. The alert is an event, told once: nothing is active to clear.

## What to do

1. Read the reason in the warning, or in `log sysupdate`, which has the line "the wanted check NAME failed". `update checks` lists each check with its command; run the command by hand to see what it says.
2. Run `changes` to see what changed with the update, and mend what the check looks at.
3. If the check itself is wrong, change it in `/system/settings/sysupdate/health.toml`, or take it out with `elevate update checks remove NAME`.
4. If a failure of this check should have sent the machine back, make it required: `required = true` in its `[[check]]`. A required check that fails during the next update's try does that.
