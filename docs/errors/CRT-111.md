# CRT-111: The chain does not lead to an authority this server trusts

`cert add` checks that the system's authorities (`/system/settings/ssl/certs/ca-certificates.crt`, which holds any authority you added) vouch for the certificate, for a TLS server, with the other certificates in the file as intermediates. The chain stops at an issuer that no authority of the system signed, and the line names it. This is most often a file that has the server's certificate and lacks the intermediate certificate that your authority gives with it, which belongs after the server's certificate. Chrome fetches a missing intermediate by itself; other browsers refuse the certificate. Nothing was added.

## What to do

1. Take the whole chain the authority sent, often called `fullchain` or `chain`, and put the server's certificate first, then the intermediate certificates in order, each a PEM block, in the one file.
2. If your authority is a private one, that the clients trust and this machine does not, either add the authority's certificate to the system's authorities (dukovo-certificates(7)), or take the certificate as it is with `--untrusted`: the Upload dialog's choice "It is not from an authority this server trusts". Clients that do not trust the authority will warn.
3. Add it again: `elevate cert add NAME --chain FILE --key FILE`, with `--replace` when the name exists and was added by hand.
4. To check that it worked, run `cert show NAME`: it says that the system's authorities vouch for it.
