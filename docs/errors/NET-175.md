# NET-175: The update server answers over IPv4 but not over IPv6

This is a warning. The machine has an IPv6 address, and the update server has an IPv6 address, but a connection over IPv6 does not work while one over IPv4 does. Programs that try IPv6 first wait for it to fail before they use IPv4, which makes the network seem slow.

## What to do

1. Run `ip -6 route` to see whether the machine has an IPv6 default route; the router may give addresses but no route, or the network may not carry IPv6 beyond its own.
2. Check that the router gives IPv6 addresses and routes: its settings may turn IPv6 off, or its provider may not give any.
3. Or turn IPv6 off for the card with `ipv6 = no` in its section of /system/settings/network, and run `service netd reload`.
4. Run `netcheck --internet` again.

## See also

netcheck(8), network(5), ip(8), the handbook's chapters "Networking" and "Checking the network".
