# NET-141: The clock was not set from a time server

This is a warning, as the network works without it. timed has not set the clock from a time server since the machine started, or last did so more than a day ago. A wrong clock makes a TLS certificate look not yet valid or no longer valid, which is NET-174, and puts the wrong time in files and logs.

## What to do

1. Run `timedatectl timesync-status` to see which servers timed asked and what each said.
2. Check that a time server can be reached. timed asks NTS servers, on TCP port 4460 and UDP port 123, and then a plain NTP server; a network that blocks them stops it. /system/settings/timed names the servers it asks.
3. A machine that was only just started has not asked yet: wait a minute and run `netcheck` again.
4. If the machine cannot reach a time server at all, stop timed with `service timed stop` and set the clock by hand with `timedatectl set-time`.

netcheck(8), timed(8), timed(5), timedatectl(1), the handbook's chapters "Networking" and "Checking the network".
