# ADM-126: The console keeps no journal or tasks now

The console keeps what changed, the earlier versions of the settings files and its long tasks in one file, `/system/state/admind/store.db`. admind could not open it when it started, so "What changed" and the tasks are not there, and an action that runs as a task is not started. Everything else in the console works.

The detail says what is wrong, and `elevate log -s admind` has the line from the start with the reason: the folder is missing or full, the file is not a database, or it was made by a newer admind than this one.

## What to do

1. Read the log line: `elevate log -s admind`.
2. Free the room, or put the folder right: `/system/state/admind` belongs to admind and is mode 0700.
3. If the file is damaged and its history is not wanted, stop admind, move `store.db` away and start admind again: it makes a new one. The journal and the earlier versions start again from that moment.
4. `elevate service admind restart` opens the store again. That ends every console session, so everyone signs in again.
