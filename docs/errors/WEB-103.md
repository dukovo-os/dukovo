# WEB-103: nginx's check failed, so nothing was changed

Before a change goes live, `website` has nginx check its settings, as the account nginx, so that a mistake never stops the sites that run. It checks twice: first the settings as they are now, before any change, so that a broken hand edit is never restarted into; then the new set of site files, written to a folder of its own beside a copy of `nginx.conf`, before any file is live. This message says that one of the two checks failed. The change was taken back as far as it had gone, the copy and the folder were removed, and nothing is live that was not before. The line holds nginx's own words, with the file and the line of the mistake. The path of a site's file in it is the real one in `/system/settings/websites`.

## What to do

1. Read nginx's words in the line: the file, the line number and what nginx did not accept.
2. If the file is a site's, in `/system/settings/websites`, it was edited by hand or by another program. Fix the line, or put the file back as it was: the Overview page of the web console shows the change under What changed, and puts it back. A site file you do not need can be removed with `elevate website remove NAME`.
3. If the file is `nginx.conf` or one it includes, fix it with `elevate nano /shared/services/org.nginx.nginx/nginx/conf/nginx.conf`.
4. To check that it worked, run `elevate website check`: its check passes. Then run the command that stopped again.
