# APP-103: No catalog could be read

bundled reads each catalog that is turned on anew, with the keys and the signed metadata it trusts, before it lists or fetches anything. `bundle search --json`, `bundle sheet` and `bundle install ID` give this error when it could read none of them. The line names each catalog and why it could not be read: the network or the catalog's server did not answer, its address or its first root is wrong, or what it published is out of date or fails a check. Nothing was found, fetched or kept. `bundle search` without `--json` reads such a catalog as it was last read and says so.

## What to do

1. Read the reason after each catalog's name. A reason that names the network, a name that does not resolve or a connection that did not open is a connection problem: `netcheck` says which layer fails, and the Updates page in the web console shows whether the machine reaches its update server.
2. Run `bundle catalog`: it lists each catalog with when bundled last read it. A time followed by `!` is a catalog whose metadata has expired, which the catalog's publisher renews.
3. For a catalog an administrator added, check its address and its root file: `elevate bundle catalog remove NAME`, then `elevate bundle catalog add NAME URL ROOT-FILE`, with the root file the publisher gives.
4. To check that it worked, run `bundle search --json`: `unread` is empty, or lists only the catalogs that are still down.
