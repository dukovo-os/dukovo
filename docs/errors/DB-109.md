# DB-109: The file is not a copy of a database that can be put back

`database restore` puts back a copy that `pg_dump -Fc` wrote, which is what PostgreSQL's backup hook makes of each database before every backup. Before it makes anything, it opens the file once, without following a link, and checks that it is a regular file, at most 64 GiB, that starts as such a copy does. The words before the ID say which of these it is not: the file is not there, it is a link, it is not a file, it is too large, or it does not start as a copy made with `pg_dump -Fc` does (a plain SQL file, a tar or a folder from another `pg_dump` format is not one). Nothing was made or changed.

## What to do

1. Run `elevate database copies NAME`: it lists the copies of the database, the newest first, with the path of each.
2. Run `database restore` again with one of those paths after `--from`.
3. A file that you made yourself must be written with `pg_dump -Fc`. A copy that is plain SQL goes in with `elevate psql -U postgres -d DATABASE -f FILE` into a database you made first.
4. A copy in a snapshot is where the snapshot of `/shared` holds it, so it is gone when the snapshot is pruned. Run `snap list /shared` to see which snapshots there are.
5. To check that it worked, run `elevate database list`: the restored database is in it.
