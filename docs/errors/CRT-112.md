# CRT-112: The key is not the certificate's, or not one the system signs with

`cert add` reads the private key and checks it against the first certificate of the chain, the server's. Either the key is of another certificate, as when the key of an earlier certificate is in the file or the files of two sites were mixed up, or it is of a kind the system cannot sign with. RSA, ECDSA and Ed25519 keys are taken; the line says what was found. Nothing was added.

## What to do

1. Use the key that was made with the certificate request: the file that your authority's tool wrote beside it, not the one of an earlier certificate. `openssl x509 -in CERTIFICATE -noout -pubkey` and `openssl pkey -in KEY -pubout` print the public keys of the certificate and of the key; they are the same text when the two belong together.
2. If the key is of another kind, make a new key of a kind the system takes, a new request, and have the authority issue the certificate again.
3. If the key file is encrypted, which its first line, `BEGIN ENCRYPTED PRIVATE KEY`, shows, take its passphrase off first, as `openssl pkey -in KEY -out PLAIN` does. `cert add` says so in its own words.
4. The key goes in a file of its own, one key and nothing else. On the Upload dialog, paste or choose the certificate and its chain in the first field and the key in the second.
5. Add it again: `elevate cert add NAME --chain FILE --key FILE`.
