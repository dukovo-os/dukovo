# MET-110: A memory device corrects many errors

One memory device had as many corrected errors in the last 24 hours as `dimm_corrected_per_day` says (24 unless set in `/system/settings/metrics.toml`). The title names the device by its place on the board and says the count; when the kernel's record had dropped its oldest lines, the count is the one since the start scaled to a day, and the title says "about". The warning is cleared when the device is under three quarters of the line.

Corrected errors lose nothing, but a device that needs many corrections a day is often starting to fail. The same count is `ras.dimm{NAME}` in the history, for each step.

## What to do

1. Run `hardware errors` to see the device, and `metrics show 'ras.dimm{NAME}' --since 1d` to see when the errors came.
2. Restart the machine and choose *Test the memory* in the start menu, and follow HW-162.
3. If the line is too low or too high for this machine, set `dimm_corrected_per_day` in the `[warnings]` table of `/system/settings/metrics.toml` and run `service metricsd reload`.
