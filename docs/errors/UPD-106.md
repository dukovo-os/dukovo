# UPD-106: A restart is pending, or changes bisect runs

`changes bisect` finds which change broke a start by restarting the machine for each try, and a restart or a shut down of the machine has a time of its own. The console does not let the two meet. It refuses to start a search while a restart or a shut down is pending, and refuses to restart or shut down the machine while a search runs: a restart that comes between the tries would make a try that is not the one the search chose, or end it. Nothing was started.

## What to do

1. If a restart or a shut down is pending, the Hardware and Updates pages say when ("restarts at 3:00 AM") with **Cancel**; at a terminal `elevate shutdown -c` cancels it. Or let it happen, and start the search after.
2. If a search runs, `changes bisect --status` follows it, and the Updates page shows its tries. It ends by itself after its last try. `elevate changes bisect --stop` stops it between tries.
3. Ask again. To check, `changes bisect --status` says that no search runs.
