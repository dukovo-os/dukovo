# APP-101: No catalog lists that app

`bundle sheet ID` and `bundle install ID` look for the app's ID in each catalog this computer trusts that is turned on, which bundled reads anew, or only in the catalog that `--from` names. None of them lists it, so there is no file to fetch. Nothing was fetched, installed or kept. When a catalog could not be read, the line says so after the first words: the app may be in that catalog, and APP-103 explains what stopped it.

## What to do

1. Check the ID's spelling. An app's ID is a reverse DNS name in lowercase, such as `org.nginx.nginx`, with its line after an `@` when it has one, as `org.nodejs.node@22`.
2. Run `bundle search WORD` with a word of the app's name: it lists the newest version of each bundle the catalogs list whose ID or name holds the word, with the ID to use.
3. Run `bundle catalog`: it lists the catalogs, whether each is on, and when bundled last read it. An app in a catalog that is off is not found.
4. If the app comes from a catalog this computer does not have yet, an administrator adds it with `elevate bundle catalog add NAME URL ROOT-FILE`. An app from a file installs with `bundle install FILE.dkv`.
5. To check that it worked, run `bundle sheet ID`: it shows the sheet of the app.
