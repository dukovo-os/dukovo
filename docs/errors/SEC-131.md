# SEC-131: The update server has not been looked at in a long time

Dukovo looks at the update server once a day, ten minutes after the computer starts and then each day, and keeps when it last did. The line says that the last look was more than 7 days ago, or that there has been none on a computer that has been up for over an hour. While the server is not looked at, nobody is told of an update, so security fixes wait without anyone knowing. The cause is usually that the computer is off most days, has no network or cannot reach the update server, or that `updates.toml` has `check = "off"`.

## What to do

1. Run `elevate update check`. If the server cannot be reached, it says why: no network, a name that does not resolve, or a certificate that is not valid, which a clock that was never set causes (see SEC-140).
2. Run `cat /system/settings/sysupdate/updates.toml`. If it has `check = "off"` and you did not mean it, take the line out: the default is `notify`.
3. Run `service updated explain` to see whether the updater runs. It starts after the network, so a computer with no network never reaches it.
4. To check that it worked, run `elevate dukovo-check`: the line for `last check` passes with today's time.
