# WEB-102: nginx's settings lack what the websites need

`website` keeps each site as a file in `/system/settings/websites`, and nginx serves it only when its `nginx.conf` includes that folder. Each site also writes its requests to a file of its own, in a format that `nginx.conf` defines. The `nginx.conf` of the bundle has three parts for this, and an update puts them on a machine whose `nginx.conf` was never changed by hand. One that was changed keeps its text, with the bundle's beside it as `nginx.conf.default`, so it lacks them. `website` never edits `nginx.conf`, which is the administrator's file, so it stopped, and nothing was changed.

The three parts are:

- in the default server, before `location / {`, so that the folders of the websites are served by their own servers and never under the machine's address:

  ```
  location ^~ /sites/ {
      return 404;
  }
  ```

- at the end of the `http { }` block, after the commented HTTPS server:

  ```
  include /system/settings/websites/*.conf;
  ```

- in the `http { }` block, before the servers, the format of the sites' own logs, which holds the time, the status and the bytes sent of each request and nothing that says who made it:

  ```
  log_format site '$msec $status $body_bytes_sent';
  ```

## What to do

1. Open nginx's settings: `elevate nano /shared/services/org.nginx.nginx/nginx/conf/nginx.conf`. The file `nginx.conf.default` beside it is the bundle's, with all three in place.
2. Add the line or lines that are missing, in the places above, and save.
3. To check that it worked, run `elevate website check`: its `nginx_conf` says that the file includes the folder, that no site is hidden and that the sites' log format is defined, and nginx's check passes.
4. Run the command that stopped again.
