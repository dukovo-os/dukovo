# SEC-150: A service gave up

Spark started a service, it failed, and after the number of failed starts in a row that its file allows, Spark stopped trying: the service is failed, and the services that require it are stopped with it. The line names each one. A service that was stopped by a person, or is off, is not a fault and is not listed. Whatever the service did, such as keeping a log, answering a connection or taking a backup, is not being done.

## What to do

1. Run `service NAME explain` for each service named. It says in a sentence why it is in its state, and what to do.
2. Run `service NAME logs` to read what it said as it failed, and `service NAME status` to see how it ended: its exit code, or the signal that killed it.
3. Mend the cause: a setting in its file that is wrong (`service check NAME` checks the file), a disk that is full, a service it requires that is not running, a file it needs that is not there.
4. Run `elevate service NAME start`. It starts the service afresh and counts its failures from the beginning. `service list --failed` lists those that are still failed.
5. To check that it worked, run `elevate dukovo-check`: the line for `failed` passes.
