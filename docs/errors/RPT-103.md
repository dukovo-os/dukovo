# RPT-103: No key of the security team is set

A report for the security team, drafted with `--security` or by the box of that name on the Report a problem page, is encrypted with age to the keys in a file of recipients, so that only the team reads it, before it is queued. reportd found no key to encrypt to: the file that `security-recipients` in `report.toml` names is not there, cannot be read or holds no `age1…` line, or the system's own, `/system/resources/report/security-recipients.txt`, is missing. It does not send a security report in the open. Nothing was drafted or sent.

## What to do

1. Write to security@dukovo.org instead, with the details a report would hold, and no more than a message of that kind needs.
2. If `report.toml` sets `security-recipients`, check the path: the file must exist, be readable by reportd, and hold one `age1…` recipient on each line (`#` starts a comment). Take the line out of `report.toml` to use the system's own key.
3. If the system's own file is the one that is missing, that is a fault of this installation: say so in the message to that address.
4. A report that is not about a security problem needs no key: choose another kind of problem.

report(1), reportd(8), report.toml(5), the handbook's chapter on reporting a problem.
