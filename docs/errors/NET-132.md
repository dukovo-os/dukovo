# NET-132: No DNS server answers

resolved has a DNS server to ask, but none of those on this network answered a question, twice. The message names them. Names cannot be looked up while no server answers. With `--internet`, the servers beyond the local network, such as a public resolver, are asked too, and these too did not answer.

## What to do

1. Run `resolvectl status` to see which servers resolved asks, and where each came from: a `servers =` line in /system/settings/resolved replaces what DHCP gave, so a server named there that is gone or mistyped is the usual cause.
2. Check that each server is on and reachable from this network: `ping` with its address.
3. Name another server with `servers =` in /system/settings/resolved, such as the router's address, and run `service resolved reload`. Remove the line to use the DHCP server's again.
4. A server named over TLS or HTTPS, or one that resolved is set to ask only over TLS, is asked for a connection, not a question: check that nothing blocks its port, 853 for TLS and 443 for HTTPS.
5. Run `netcheck` again: it passes the DNS layer once a server answers.
