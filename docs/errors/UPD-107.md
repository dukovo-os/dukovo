# UPD-107: An update that fixes a flaw is not put off

`update later` puts the reminder of an update off for a day or a week: the Updates page and the daily notice leave it out until then. It does not do so for an update that fixes a security advisory, because a reminder that runs out by itself is not a good way to keep a fix waiting. The command refused, and nothing was changed. It says which advisory the update fixes ("Dukovo 1.0.0-alpha.2 fixes DKSA-2026-0007 (high)"), or that it could not tell: when the advisories could not be read, which happens when the update server cannot be reached, it fails closed, and treats the update as one that fixes something.

A reminder already put off ends by itself in the same two cases: when an advisory is published that the update fixes, the next look at the updates shows the offer as it was before, and the reminder is not kept.

## What to do

1. Take the update. The Updates page and `update check` name it; `elevate update apply` stages the system's, and `elevate bundle update` takes an app's. A fix is the reason to take it.
2. If it must wait, hold it: `elevate update hold ITEM --why "text"` keeps it back, and says why to whoever looks, until `elevate update unhold ITEM`. A hold is a choice that someone releases; a reminder is not.
3. If the advisories could not be read, check the connection (`update check` says what could not be reached), and ask again.
4. To check, run `update check`: it lists the update, and `update settings` shows no reminder for it.
