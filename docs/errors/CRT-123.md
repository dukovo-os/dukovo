# CRT-123: A certificate could not be got for a day

`cert get` asked an authority for a certificate by HTTP, and the order failed after it began. `cert` kept what it was asked for, and certd asks again by itself: every hour for a day, then every 6 hours, until 14 days after the first try. When the first day is over and the certificate is still not got, certd raises the alert `certificate:NAME`: "The certificate NAME could not be had for a day: WHY". It is a warning. The reason is the authority's or this machine's, in words, as the last try said it. It clears by itself when a try works, or when the order is forgotten or the certificate is removed.

If the same certificate is running out as well, the alert for that one is shown in its place, with its own page (CRT-121 or CRT-122).

## What to do

1. Read the reason in the alert, with `cert wanted` (it shows when each try was and when the next is), `cert history NAME`, and `log certd`. The usual ones have a page: the name does not lead to this machine (CRT-101, CRT-102), port 80 is closed or held (CRT-103, CRT-106), the clock is wrong (CRT-105). An authority that refuses for its limits says so, and certd does not ask before the time it names.
2. Mend the cause. certd tries again within the hour, or at once with `elevate service certd reload`, and the alert clears when a try works. To order by hand and see each step, run `elevate cert get NAME` again with the same names: it makes the order anew, and certd keeps trying from that day.
3. If the certificate is not wanted any more, run `elevate cert forget NAME`: certd stops asking and the alert goes.
4. To check that it worked, run `cert list`, which shows the certificate, and `cert wanted`, which no longer lists it.

certd gives up 14 days after the first try; that is CRT-124.
