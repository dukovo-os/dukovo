# CRT-101: The name does not lead to this server

Before it asks an authority for a certificate by HTTP, `cert get` looks each name up with the system's resolver, as the Certificates page's checks do (`cert get NAME --check`). The line names a name that resolves to no address at all. The authority looks the name up itself and connects to the address it finds, so a name with none cannot be proved by HTTP. Whether an address that does resolve is this machine's cannot be told from here: only the authority's own try shows it, which `cert get --dry-run` makes against its staging service without installing anything. Nothing was ordered.

## What to do

1. At the provider that holds the name's DNS, give the name an A record, and an AAAA record for IPv6 if the machine has an address of that kind, that lead to this machine. Each name of the certificate needs its own records.
2. Wait for the record to spread, which its time to live says, then run `dig NAME`: it shows what this machine finds.
3. If the name cannot lead to this machine, because it has no public address or the name is not yours to point, prove the name by DNS instead: `elevate cert get NAME --dns`. A wildcard name has to be proved that way.
4. To check that it worked, run `elevate cert get NAME --check`: the line for the name passes. `elevate cert get NAME --dry-run` then asks the staging authority to try for real.
