# SEC-112: Blocking of addresses that guess passwords is off

`/system/settings/blocking.toml` says `on = false`. authd counts the wrong passwords that come from each address: over SSH, to the sharing service, at the web console and for a help session. When one address has typed too many in a short time, authd has the kernel drop its new connections to those sign-in ports for a while, and for longer each time it comes back. With blocking off, an address may keep guessing as fast as each wrong password's own wait allows, for as long as it likes. Blocking is on by default.

## What to do

1. In `/system/settings/blocking.toml`, set `on = true`, or take the line out, which means on. The other settings in the file, the number of tries and the length of a block, can stay as they are.
2. authd reads the file when it starts and when an administrator changes the settings. If the check still warns, run `elevate service authd restart`.
3. If a network you trust, such as the office, gets blocked by one person's typing mistakes, leave blocking on and name that network in the file's `never` list: `elevate firewall never-block 192.168.1.0/24`.
4. To check that it worked, run `elevate dukovo-check`: the line for `blocking` passes. `elevate firewall blocked` lists the addresses that are blocked now.
