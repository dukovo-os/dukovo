# SEC-112: Blocking of addresses that guess passwords is off

`/system/settings/blocking.toml` says `on = false`. authd counts the wrong passwords that come from each address: over SSH and to the sharing service, whatever account they name. When one address has typed too many in a short time, authd has the kernel drop its new connections to the sign-in ports for a while, and for longer each time it comes back. With blocking off, an address may keep guessing as fast as each wrong password's own wait allows, for as long as it likes. Blocking is on by default.

## What to do

1. In `/system/settings/blocking.toml`, set `on = true`, or take the line out, which means on. The other settings in the file, the number of tries and the length of a block, can stay as they are.
2. Nothing needs restarting: authd looks at the file before each request it answers and reads it again when it changed, and says what it now does in the audit log. If the check says that the file does not read, the file has a mistake that the line names; authd keeps the settings it had until it is fixed, and `log -s authd` says why.
3. If a network you trust, such as the office, gets blocked by one person's typing mistakes, leave blocking on and name that network in the file's `never` list: `elevate firewall never-block 192.168.1.0/24`.
4. To check that it worked, run `elevate dukovo-check`: the line for `blocking` passes, and says the settings it found, such as `5 wrong tries in 10 minutes block an address for 10 minutes, doubling up to 1 day`. `elevate firewall blocked` lists the addresses that are blocked now.
