# ADM-109: The request did not come from the console's page

A request that changes something has to come from the console's own page, and this one did not pass the checks that say so. They keep another site's page from sending requests to the console with a person's cookie. The detail says which check failed:

- `Origin` is missing, or is not the console's own. It is `https://` and the name and port the browser asked for, such as `https://duke-nas.local:9090`.
- `Sec-Fetch-Site` says the request came from another site.
- The session's token, `X-Dukovo-CSRF`, is missing or wrong. The page gets it when it loads, so a page left open while the console restarted has an old one.

The sign-in requests carry no token yet, so they pass the first two checks only.

## What to do

1. Reload the console's page and try again.
2. Open the console by a name or an address it answers to (the machine's sign-in screen shows one), with no proxy between that changes the `Host` or `Origin`.
3. A program that is not a browser has no way to pass these checks. A script uses an API token instead, in an `Authorization: Bearer` header, for the console's actions (ADM-115, ADM-124).
