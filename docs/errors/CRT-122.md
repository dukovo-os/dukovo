# CRT-122: A certificate has run out

A certificate's end day has passed. Services that serve it, such as nginx or the web console, go on using it, and each client that checks refuses it with a message that it has expired: a browser blocks the page, and a program that connects fails. certd raises the critical alert `certificate:NAME` with the same words as its sign-in notice, "The certificate NAME ran out on DATE", and it clears when the certificate is renewed, replaced or removed. A certificate that certd renews by itself gets here when its renewals failed for weeks (CRT-121); one that was added by hand, or proved by DNS, when it was not renewed in time.

## What to do

1. For a certificate from an authority by HTTP, mend what CRT-121 names, then run `elevate cert renew NAME`.
2. For one proved by DNS, run `elevate cert get NAME --dns` again, and add the records it shows.
3. For one added by hand, get the new certificate from where it came, and add it: `elevate cert add NAME --chain FILE --key FILE --replace`. The services that name it read it again at once.
4. For this-machine, certd makes a new one when its clock is right: see CRT-105, and run `elevate service certd reload`.
5. If nothing uses the certificate any more, take it away with `elevate cert remove NAME`.
6. To check that it worked, run `cert list`: the certificate has days left, and the alert clears at certd's next look.
