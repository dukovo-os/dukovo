# UPD-105: A release that fell back is held

An update failed its health check, and the machine went back to the version before it (UPD-101). So that a machine that updates by itself does not stage the same release at its next daily check and fall back again, sysupdate holds the release it fell back from: it writes `system = "VERSION"` under `[hold]` in `updates.toml`, unless a hold there names that version or a newer one already, and records in `/system/state/sysupdate/held.json` that the hold came from a fall back, with the time and the start. The failure notice and the alert say so, "VERSION is held: it is not staged again until you release it", and `update check` shows the system as held and why. A hold is for one version: a newer release is taken as usual, so a fix that comes in the next one is not kept out.

## What to do

1. Find out why it fell back. The Updates page shows what happened, and `changes --failed` says what failed and what changed. Follow the page of the error ID it names.
2. Do nothing if a newer release is coming: the next check offers it, and it is staged as any release is.
3. To try the held release again once its cause is mended, run `elevate update unhold system`, which takes the hold out of `updates.toml` and removes `held.json`, then `elevate update apply`.
4. To check, run `update check`: the system is no longer held.
