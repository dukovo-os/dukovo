# ADM-141: The certificate does not name the address this browser uses

**Use for this console** was chosen for a certificate, and the address this browser opened the console at, such as `192.168.1.10`, is not one of the names the certificate holds. The console would serve the certificate from the next connection on, and this browser would then warn of it on every new connection. So the console refuses before it changes anything. It refuses too when it cannot read the certificate's names, since it does not change what it cannot check. Nothing was changed.

## What to do

1. Open the Certificates page and read the names of the certificate. Run `cert show NAME` for the same list at a terminal.
2. Open the console at one of those names, such as `https://duke-nas.example.org:9090/`, and choose **Use for this console** there. The name has to lead to this machine, and it has to be one the console answers to: the machine's own name, or a name of the certificate it serves now (ADM-114).
3. If the certificate names something that is not this machine, give the machine that name first, under Name and domain on the Certificates page, or get a certificate that names the machine, with `elevate cert get`.
4. The change is a trial of 300 seconds. Keep it once the page shows that it came back over the new certificate. Left alone, Spark puts both files back, and the console serves the certificate it had.
