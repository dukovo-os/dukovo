# UPD-102: Rescue could not be brought up to date

Once a new version proves itself, Dukovo writes Rescue again from it, so that Rescue starts, and reinstalls, the version that runs. This time it could not, on the EFI system partition the line before this one names, and it says why: most often the partition has no room for the new copy beside the old one. The copy that was there is untouched and still starts; it holds an older version.

## What to do

1. Run `log sysupdate-stage` to read why, and `sysupdate status` to see which version Rescue holds.
2. If the partition is too small, free room on it, or make it larger with "Repair startup" on the install stick (dukovo-install(8)), which puts Rescue back on the partition it makes again.
3. Nothing else is needed: Dukovo tries again at each start until Rescue holds the version that runs.

## See also

sysupdate(8), dukovo-rescue(8), dukovo-install(8), the handbook's chapter on updates.
