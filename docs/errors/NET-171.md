# NET-171: The update server's name does not resolve

With `--internet`, `netcheck` looked up the name of the server in the update settings, and no address came back. The DNS servers answered, as the layer before it passed, so the name is wrong, or the servers do not know it.

## What to do

1. Read the `server` setting in /system/settings/sysupdate/updates.toml, and check the name for a mistake.
2. Run `resolvectl query` with that name to see what resolved says of it. A server on the local network, named in a `.local` name or a private zone, may need its own DNS server: name it with `servers =` in /system/settings/resolved.
3. A network that blocks or rewrites DNS answers, such as a captive portal that has not been signed in to, can stop a name from resolving: sign in to its page.
4. Run `netcheck --internet` again.

netcheck(8), updates.toml(5), resolvectl(1), resolved(5), the handbook's chapters "Updates, snapshots, backups and recovery" and "Checking the network".
