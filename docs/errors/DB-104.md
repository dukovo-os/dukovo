# DB-104: PostgreSQL's settings did not pass its check, so nothing was changed

`database allow` and `database deny` change the lines of `pg_hba.conf` that `database` keeps between its two marks, the settings of `ALTER SYSTEM`, and the rules for port 5432 that `database` keeps in the firewall's rules. Before the change takes effect, `database` asks PostgreSQL to check the files as they are on disk: `pg_hba_file_rules` and `pg_file_settings` list each line they cannot read. When a line has an error, or when the server does not come back after the restart, `database` puts `pg_hba.conf` back as it was, resets the settings it changed, puts back the service file's override and the firewall's rules, has the firewall load them again, and restarts PostgreSQL again if it had restarted it. A firewall that does not take the new rules ends the command the same way. The line has PostgreSQL's own words and the line number of the file. The error is usually a line of your own: `database` changes nothing outside its block.

`database list` shows the same words under its problems when `pg_hba.conf` has an error from a hand edit.

## What to do

1. Read the line: the file, the line number and what PostgreSQL did not accept.
2. Fix it: `elevate nano /shared/services/org.postgresql.postgresql/postgres/data/pg_hba.conf`, or `postgresql.conf` or `postgresql.auto.conf` beside it, whichever the line names. Then run `elevate service postgresql reload`.
3. Run `database allow` or `database deny` again.
4. To check that it worked, run `elevate database list`: it lists no problem.
