# ADM-102: That code is not right

authd did not take the code that was typed as a second step. It appears when a code is given at sign-in (the six digits from the authenticator app, or a recovery code), to unlock the console, or to confirm the app when it is added. The detail says which of these it was:

- **The code is not right.** The digits are not the app's for this moment. An app's code changes every 30 seconds, and the console takes the one before, the current one and the one after, so a phone whose clock is more than half a minute out gives codes that never fit.
- **The code was used already.** Each code works once, even inside its own 90 seconds. Wait for the app to show the next one.
- **It is not a code.** An app's code is 6 digits. A recovery code is 16 letters and digits, such as `ABCD-EFGH-IJKL-MNOP`; the dashes and spaces do not matter, nor does the case. Unlocking takes the app's code and no recovery code.

A wrong code waits as a wrong password does (see ADM-101).

## What to do

1. Wait for the app to show a new code, and give that one.
2. Check that the phone sets its time automatically.
3. If the phone or the app is lost, sign in with a recovery code. Each works once, and the page that makes new ones is under Second step, once you are in.
4. If the app and every recovery code are gone, the account has no way in to the console. An administrator removes its second steps by deleting its file, `elevate rm /system/state/authd/console/NAME.toml`, which also forgets the account's passkeys, trusted browsers and API tokens; the account then signs in with its password, and adds the second step again.
