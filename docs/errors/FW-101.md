# FW-101: The CPU microcode of a firmware set is damaged

The kernel checks the CPU microcode the firmware set names before it uses any of it. Its data failed those checks, so the processor runs the microcode it started with. During the set's first start, the firmware update fails and the computer goes back to the set before it by itself.

## What to do

1. Run `sysupdate firmware` to see which set each slot names.
2. Stage the set again, or a newer one, with `sysupdate firmware stage`: the store keeps each file by its SHA-256, so a damaged copy is fetched anew.
3. If it happens again with the same set, report it with the output of `changes --failed`.

## See also

sysupdate(8), radix-sysfs(5), changes(1).
