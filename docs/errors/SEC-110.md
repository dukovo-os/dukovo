# SEC-110: Passwords sign in over SSH

SSH is on, and `/system/settings/ssh/sshd_config` has `PasswordAuthentication yes`. Anyone who can reach port 22 can try to guess a person's password, and machines on the internet try every address they can find, all day. Dukovo makes each wrong password wait, and blocks an address that keeps guessing (SEC-112), but a password that is guessed once opens the account, and a key cannot be guessed. A default install has SSH off, and takes keys alone once it is on.

## What to do

1. From the computer you sign in from, put your key on this one. If you have none, make one there with `ssh-keygen -t ed25519`. Then run `ssh-copy-id alice@dukovo`, with your name and this computer's name, or add the key's line to `~/.ssh/authorized_keys` in your home here. Keys of the kinds ed25519, ecdsa-sha2-nistp256 and ecdsa-sha2-nistp384 are taken.
2. Sign in with the key, as `ssh alice@dukovo`, and keep that session open until the last step is done.
3. In `/system/settings/ssh/sshd_config`, change the line to `PasswordAuthentication no`, or take it out: keys alone is the default.
4. Run `sshd -t`, which checks the file, then `elevate service sshd reload`. Open a second session with your key to see that it still signs in.
5. To check that it worked, run `elevate dukovo-check`: the line for `passwords` passes, and says that only keys sign in.

If passwords must stay, say who may use them, as SEC-111 says, and keep blocking on (SEC-112).
