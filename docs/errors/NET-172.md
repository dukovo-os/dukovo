# NET-172: The update server does not answer

With `--internet`, `netcheck` found the address of the update server, but a connection to its port was refused or timed out, or it was made but the TLS session could not be set up for a reason other than the certificate. The message names each address it tried, up to two of each IP version the machine has an address of, and why each failed.

## What to do

1. Check the address and port in the `server` setting of /system/settings/sysupdate/updates.toml.
2. Check that the server is up: try it from another machine, or with `curl` here.
3. Check that nothing between this machine and the server blocks the port, usually 443: a company's firewall may allow only a proxy.
4. If the message says the TLS connection fails though the server answers, check that the port speaks TLS: an `http://` server is used with a plain connection, and an `https://` one needs the port of a TLS service.
5. Run `netcheck --internet` again.

## See also

netcheck(8), updates.toml(5), curl(1), the handbook's chapters "Updates, snapshots, backups and recovery" and "Checking the network".
