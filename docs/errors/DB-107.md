# DB-107: The firewall's rules are being tried

`database allow`, `database deny` and `database remove` keep a block of rules for port 5432 in the firewall's rules, `/system/settings/firewall`, so that the port is open to the networks that a database is opened to and to no other. A change to those rules is being tried now (`firewall allow ... --try`). Spark keeps one trial for the file at a time and puts the file back as it was before the trial when the trial ends, so a block written now would be lost with it, and the port would be left as the trial found it. Nothing was changed: not `pg_hba.conf`, not PostgreSQL's settings, not the firewall, and `database remove` dropped no database.

## What to do

1. Keep the change being tried with `elevate firewall keep`, or undo it with `elevate firewall undo`. The Firewall page shows the same trial with **Keep this change** and **Undo now**.
2. Or wait: Spark undoes the trial when its time runs out, and `firewall list --json` says how long is left.
3. Run `database allow`, `database deny` or `database remove` again.
4. To check that it worked, run `elevate firewall list`: the rules for port 5432 are there, between the two comment lines of `database`.
