# CRT-124: certd gave up getting a certificate

certd asked an authority again and again for a certificate that `cert get` could not get, and stops. It does so when the order has failed for 14 days, or earlier when what it needs is gone: the account at the authority was taken away and the order had not agreed to its terms (`--agree-terms`) for a new one to be made, or a certificate of that name was added by hand since, which a new one would replace. It keeps the record, so that `cert wanted` still shows the reason and the alert `certificate-given-up:NAME` stays: "certd gave up getting the certificate NAME: WHY". It is a warning. Nothing is asked of the authority any more for it, and the services keep what they had.

## What to do

1. Read the reason in the alert or in `cert wanted`. If the authority kept refusing, the cause is the one the reason names; mend it first (CRT-101 to CRT-106 say how).
2. Get the certificate again: `elevate cert get NAME` with the names it is for. It makes the order anew, and if it fails again certd tries again for 14 days from that day. When it works, the record and the alert go.
3. If the certificate is not wanted any more, run `elevate cert forget NAME`: the record and the alert go. A name that was added by hand since is kept as it is; `cert forget` leaves it alone.
4. To check that it worked, run `cert wanted`, which no longer lists it, and `alerts list`.
