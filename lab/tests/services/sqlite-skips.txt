# The test files of SQLite's veryquick suite that the lab's test
# services/sqlite-suite leaves out, each group with the reason it fails on
# Radix. A line is a test file as the test runner names it (its path from
# the folder that holds test/, such as test/wal.test); lines that start with
# '#' are comments, which sqlite-suite.sh strips before it compares the list
# with the files that failed. When a gap closes, its lines go: the script
# says which files on the list pass; the gaps waiting on work are in
# docs/deferred.md. A line that starts with '~' is a file the suite does not
# run at all, as the test runner's anti-pattern: one that would never end.
# Its gap's fix must take its line out by hand, as no run says it passes.

# WAL shared between connections: needs shared writable mappings of disk
# files (docs/deferred.md, Files and storage). SQLite keeps the index of a
# WAL database in the -shm file beside it, mapped shared by every
# connection, and Radix refuses that mapping of a file outside /dev/shm, so
# the first read of a WAL database that is not in exclusive locking mode
# fails with SQLITE_IOERR_SHMMAP, "disk I/O error". With the index in
# /dev/shm all of these files pass but the ones that read the -shm file
# beside the database (delete_db, e_wal, e_walauto, pager1, wal2, wal64k,
# wal9, waliter, walpersist, walro, walro2 and walsetlk). walsetlk_recover
# waits for a second process, which fails at once for the same reason and
# has finished before the test waits for it, so it would wait for good: it
# is not run.
